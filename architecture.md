# Architecture: Русская Рамаяна

## Цель архитектуры

Сайт должен вырасти из текущего `index.html` в устойчивый статический ресурс на GitHub Pages:

- главный экран работает как краудфандинговая страница;
- каталог переводов, пересказов и адаптаций ведётся как структурированные данные;
- аудио, видео, сканы, OCR и библиография подключаются постепенно;
- сбор средств прозрачно агрегируется из нескольких платформ;
- сайт остаётся простым в публикации и не требует серверной части на первом этапе.

Ключевой принцип: сначала статический сайт и JSON-данные, затем при необходимости генерация страниц из этих данных. Не начинать с тяжёлого фреймворка.

## Общая схема

```text
Материалы и решения

  |-- roadmap.md

  |

  |
  |-- index.html

  |-- compare/*.html
  |-- audio.html

Внешние хранилища
  |

  |-- samskrtam.ru
  |-- ВК
  |-- Telegram
  |-- YouTube
  |-- Boosty / Patreon / PayPal / Сбер / банк
```

## Фаза 1: сохранить текущий сайт, но добавить слой данных

На первом шаге не нужно ломать `index.html`. Нужно добавить папку `data/` и начать переносить туда то, что часто меняется.

Предлагаемая структура:

```text
data/
  site.json
  people.json
  project-status.json
  translations.json
  retellings.json
  editions.json
  audio.json
  videos.json
  timeline.json
  comparison-episodes.json
  payment-methods.json
  fundraising/
    summary.json
    reports/
      2026-06.md
```

На этом этапе страницы могут быть ещё ручными, но новые блоки должны брать данные из JSON там, где это удобно.

## Главные страницы

### `index.html`

Главная остаётся первым экраном проекта.

Функции:

- прямой краудфандинговый первый экран;
- цель `1 000 000 руб.`;
- месячная цель `166 000 руб.`;
- кнопки поддержки;
- короткое объяснение линии Гринцер -> Леонов;
- видимый вход в каталог переводов;
- вторичный вход в аудио и карту.

Главный CTA:

```text
Поддержать перевод
```

Рабочий первый экран:

```text
Собираем 1 000 000 руб. на завершение первого полного русского поэтического академического перевода Валмики-Рамаяны с санскрита.
```

### `support.html`

Отдельная страница сбора.

Содержит:

- цель и прогресс;
- публичный счётчик;
- разовый платёж;
- подписка;
- способ для зарубежных доноров;
- Сбер;
- PayPal через посредника;
- Patreon;
- банковский перевод;
- смету;
- статусы книг IV, V, VI;
- ежемесячные отчёты;
- благодарности;
- пояснение, что текущий сбор не решает проблему книги IV и не заменяет издательство.

### `project.html`

Страница проекта Гринцер -> Леонов.

Содержит:

- историю начатого Гринцером перевода;
- опубликованные книги I-III;
- проблему книги IV;
- статус книги V;
- статус книги VI;
- роль Леонова;
- роль Костиной;
- роль Гасунса;
- связь с `Литературными памятниками`: `готовится для серии`;
- видео и цитаты Леонова;
- ссылка на поддержку.

### `translations.html`

Каталог переводов, подстрочников, пересказов и адаптаций.

Важно: эти типы нужно визуально разделять жёстко.

Разделы:

- переводы с санскрита;
- подстрочники;
- пересказы;
- адаптации;
- аудио-версии;
- издания и сканы.

### `timeline.html`

Хронология русской Рамаяны.

Содержит:

- первые русские упоминания, пересказы и фрагменты;
- академические публикации;
- линия Гринцера;
- продолжение Леонова;
- цифровой корпус и текущий проект.

### `compare/sundarakanda-start.html`

Первый curated-раздел сравнительного чтения.

Начать с начала Сундараканды.

Содержит:

- санскритский источник, если можно подключить;
- перевод/подстрочник Леонова;
- другие доступные русские версии;
- краткий комментарий;
- ссылки на корпус.

### `audio.html`

Второй уровень, не первый экран.

Содержит:

- аудиокнигу 1986 года;
- длительности треков;
- внешние ссылки;
- статус доступности файлов;
- предупреждение, если файл хранится вне GitHub из-за размера.

### `media.html`

Видео и выступления.

Содержит:

- видео Леонова;
- видео Гасунса;
- доклады по Рамаяне;
- чтения фрагментов;
- расшифровки или цитаты с таймкодами.

### `data/retellings.json`

Отдельный каталог пересказов и адаптаций.

Эрман и кришнаитские материалы должны идти сюда, если это пересказ, а не перевод.

### `data/fundraising/summary.json`

Публичный агрегат для счётчика.

```json
{
  "goal_rub": 1000000,
  "monthly_goal_rub": 166000,
  "collected_rub": 0,
  "donor_count": 0,
  "updated_at": "2026-05-14",
  "sources": [
    "boosty",
    "sber",
    "patreon",
    "paypal_proxy",
    "bank_transfer"
  ]
}
```

Приватные данные доноров не должны попадать в публичный репозиторий.

## Учёт пожертвований

### Приватный слой

Вариант A: приватный CSV/Excel вне публичного репозитория.

Вариант B: Google Sheets или Яндекс Таблицы с экспортом в CSV.

Рекомендуемый путь на старте: таблица с ручным контролем и экспортом, потому что источников много и часть данных всё равно придётся сверять руками.

Черновые поля:

```text
date
platform
amount
currency
amount_rub
fee
net_amount_rub
donor_name
public_name
anonymous
reward_level
comment
source_id
```

### Публичный слой

Публиковать только:

- общую сумму;
- процент цели;
- месячную сумму;
- число доноров, если решено показывать;
- список благодарностей только с явным согласием;
- ежемесячные отчёты.

## Контентный pipeline

### Входящие материалы

Источники:

- Яндекс Диск;
- ВК;
- Telegram-каналы;
- `samskrtam.ru`;
- локальные файлы;
- YouTube.

### Аудит

Каждый материал получает статус:

- `publish-now`;
- `needs-proofreading`;
- `needs-selection`;
- `needs-processing`;
- `subscriber-only`;
- `internal`.

### Публикация

Публикуются только материалы с понятным статусом прав и технической готовностью.

## Видео и цитаты

Для видео нужно два уровня обработки:

- полный transcript, если видео важно для архива;
- короткие цитаты с таймкодами, если видео используется на странице сбора.

Начать с видео Леонова, специально снятых для сбора, затем расширять медиа-архив.

## Аудио и большие файлы

GitHub не подходит для крупных MP3 больше 100 MiB без дополнительной инфраструктуры.

Варианты:

- хранить большие MP3 вне репозитория;
- использовать GitHub Releases для отдельных файлов;
- использовать внешний хостинг;
- нарезать большие MP3 на главы или части;
- держать в репозитории только метаданные и ссылки.

На сайте аудио должно описываться через `data/audio.json`, а не вручную в нескольких местах HTML.

## Закрытые материалы для подписчиков

GitHub Pages не умеет настоящую авторизацию.

Поэтому закрытые черновики лучше выдавать через:

- Boosty;
- Patreon;
- закрытую рассылку;
- закрытую страницу на отдельной платформе.

На основном сайте можно показывать только описание бонуса и ссылки на платформы.

## Первый внедряемый этап

Минимальный первый шаг:

1. Создать `data/project-status.json`.
2. Создать `data/fundraising/summary.json`.
3. Создать `data/payment-methods.json`.
4. Добавить на `index.html` новый первый экран сбора.
5. Создать `support.html` как отдельную страницу сбора.
6. Добавить в `CHANGELOG.md` запись о первом публичном краудфандинговом каркасе.

Это даст видимый результат без полной миграции сайта.

## Второй этап

1. Создать `translations.html`.
2. Создать `data/translations.json`.
3. Создать `data/retellings.json`.
4. Вынести Эрмана и кришнаитские материалы в отдельный раздел пересказов.
5. Добавить строгие метки: `перевод`, `подстрочник`, `пересказ`, `адаптация`.

## Третий этап

1. Создать `project.html`.
2. Добавить историю Гринцер -> Леонов.
3. Добавить статусы книг IV, V, VI.
4. Добавить видео и цитаты Леонова.
5. Добавить объяснение связи с `Литературными памятниками`.

## Четвёртый этап

1. Создать `timeline.html`.
2. Создать `compare/sundarakanda-start.html`.
3. Добавить начало Сундараканды как первый сравнительный эпизод.
4. Связать страницу сравнения с параллельным корпусом на `samskrtam.ru`.

## Пятый этап

1. Создать `docs/content-inventory.md`.
2. Начать инвентаризацию Яндекс Диска, ВК, Telegram и `samskrtam.ru`.
3. Отдельно пометить материалы, которые можно публиковать сразу.
4. Отдельно пометить видео, которые нужно расшифровать.

## Что не делать на старте

- Не заводить тяжёлый фреймворк.
- Не делать поиск по текстам.
- Не пытаться хранить приватные донорские данные в публичном репозитории.
- Не переносить все материалы вручную в один огромный HTML.
- Не обещать закрытый доступ через GitHub Pages.
- Не загружать большие MP3 в обычный GitHub-репозиторий.

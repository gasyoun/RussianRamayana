## Начало работы

### С чего начать совсем с нуля?

```bash
git clone https://github.com/gasyoun/RuWritingStyles.git
cd RuWritingStyles
pip install pyyaml python-docx
# rws_pipeline.py положить в корень репозитория
python3 rws_pipeline.py --help
```

Затем смотреть `rws_onboarding.md` — там пошагово с примерами.

---

### Что вообще делает пайплайн?

Принимает корпус текстов автора → замеряет 13 стилометрических показателей → транслирует каждый показатель в поведенческое правило → сохраняет четыре файла:

```
<handle>_stylometry.md     числа и таблицы
<handle>_rules.md          поведенческие правила ← проверить вручную
<handle>_dh_section.md     DH-раздел для _style.md
<handle>.yml               машиночитаемый паспорт агента
```

Ни один из этих файлов не является финальным стилистическим портретом — они основа для ручной доработки `ClaudeStyles/<handle>-style.md`.

---

### Сколько текстов нужно для надёжного результата?

| Объём | Что работает |
|---|---|
| < 30 постов / параграфов | Только базовая стилометрия, без кейнесса |
| 30–100 | TTR, POS, синтаксис — надёжно; кейнесс — приблизительно |
| 100–300 | Все измерения работают; динамика по годам — если есть даты |
| 300+ | Полный пайплайн, включая ритм публикаций |

Для академических статей 30–50 параграфов обычно достаточно для POS и синтаксиса.  
Для Telegram-канала рекомендуется минимум 200 постов.

Выбрать формат **JSON** (не HTML).

## Стилометрия и измерения

### Что такое MSTTR и почему TTR неинформативен?

**TTR (Type-Token Ratio)** = уникальные слова / все слова.  
На больших корпусах всегда падает, даже у Толстого. Сравнивать нельзя.

**MSTTR (Moving Segment TTR)** = среднее TTR по окнам в 500 токенов.  
Нормализует влияние объёма. Сравнивать можно.

Ориентиры:

| Тип текста | MSTTR |
|---|---|
| Новостной Telegram-канал | 0.62–0.68 |
| Публицистика, блог | 0.68–0.75 |
| Академическая статья | 0.72–0.78 |
| Художественная проза | 0.80–0.85 |

Гасунс (Telegram): **0.776** — уровень академического текста в личном канале.

---

### Что измеряет Verb/Noun ratio?

Отношение глагольных форм к существительным. Диагностирует регистр:

- **> 0.25** → глагольный, разговорный стиль
- **0.15–0.25** → смешанный
- **< 0.15** → именной (много терминов и имён собственных)

Важно: низкое V/N — не плохо. Это признак терминологически плотного текста. Гасунс: 0.09 (именной стиль, обусловлен санскритской терминологией и именами).

---

### Что такое hypo/para ratio и почему он низкий у академической статьи?

**Гипотаксис** — подчинение («который», «потому что», «хотя»).  
**Паратаксис** — сочинение («и», «а», «но»).

Ожидание: академический текст > 0.40.

Если академическая статья показывает 0.15–0.25 — это авторский синтаксический отпечаток: автор строит аргументы не через развёрнутые придаточные, а через короткие утверждения, разделённые тире или точкой. Статья Гасунса: **0.147** — тот же координационный синтаксис, что в Telegram.

Это не ошибка, а идиолект. Фиксируется в стилевом портрете.

---

### Почему formality_index = 1.0, хотя текст — личный Telegram?

`formality_index` считает: `(академические маркеры) / (академические + эссеистические)`.

Маркеры эссе: «мне кажется», «я думаю», «по моему мнению».  
Гасунс их не использует — пишет «намерен», «горжусь», «следовательно». Эти слова не попадают ни в академический, ни в эссеистический словарь.

Вывод: **formality_index = 1.0 у Гасунса — не академизм**, а нейтральность. Расширить `ESSAY_MARKERS` в коде, добавив идиолектные маркеры конкретного автора.

---

### Что значит «кейнесс» и как читать таблицу?

Кейнесс (log-likelihood G²) — насколько слово статистически перепредставлено у автора относительно референсного корпуса (НКРЯ).

| G² | Интерпретация |
|---|---|
| > 2000 | Уникальная сигнатура — слово определяет идиолект |
| 800–2000 | Сильный маркер |
| 300–800 | Значимый маркер |
| < 300 | Слабый |

Недопредставленные слова — обычно абстрактные концепты («человек», «жизнь», «дело»). Автор их избегает — пишет конкретно.

---

### Что значит «ирония через архаику» в эпистемической модальности?

Стандартные словари хеджирования не включают «ибо», «сиречь», «глаголет» — они идут как нейтральные союзы. Но у Гасунса «ибо сказано в ведах…» — это псевдоцитатная ирония.

Это **ironic_cite** категория — авторская, добавляется вручную в `EPISTEMIC_MARKERS['ironic_cite']` перед запуском:

```python
EPISTEMIC['ironic_cite'] = ['ибо сказано', 'ибо', 'сиречь']
```

Для каждого нового автора — найти свои формулы в корпусе вручную.

## Интерпретация результатов

### Как быстро понять, всё ли нормально?

После прогона смотреть на пять чисел в отчёте:

```
MSTTR 0.77  V/N 0.09  H/A 1.02  hypo/para 0.249
Формальность 0.96 → реферат/курсовая
```

Сигналы тревоги:

| Показатель | Флаг | Что делать |
|---|---|---|
| MSTTR < 0.65 | Бедная лексика | Искать повторяющиеся слова в keyness |
| V/N > 0.30 | Неожиданно глагольный для академика | Проверить жанр корпуса |
| H/A > 1.5 | Очень много оговорок | Нормально для гуманитарного эссе |
| H/A < 0.5 | Почти нет хеджирования | Проверить спорные утверждения |
| hypo/para < 0.20 (для академика) | Координационный синтаксис | Стилевой отпечаток или нужна правка? |
| formality_index ≈ 1.0 | Расширить ESSAY_MARKERS | — |

### Почему в _rules.md написано «ПРОВЕРИТЬ ВРУЧНУЮ»?

Потому что матрица трансляции работает с числами, а числа не знают контекста.

Типичные проблемы, которые нужно поймать вручную:

**Противоречие:** `nominal_style_ok` (hard) и `no_nominalization` (soft) сгенерированы одновременно → оставить только первое, удалить второе.

**Ложная тревога:** `formal_academic` сгенерирован для Telegram-канала → удалить или сделать soft.

**Пропуск:** табуированные темы, авторская этика, специфика аудитории — числа не видят. Добавить вручную в `manual_limits`.

---

### Что делать с `main_intonation` — он пустой?

Это единственное поле, которое нельзя вычислить. Нужно прочитать 20–30 текстов из корпуса и сформулировать одну прескриптивную фразу: не «что написано», а «что агент должен воспроизводить».

Примеры из репозитория:

| Стиль | main_intonation |
|---|---|
| zalizniak-ocherk | Системная точность и спокойная научная уверенность |
| zalizniak-zametki | Понятная научная полемика с точной иронией |
| zalizniak-shkolnikov_1 | Ясность, уважение к читателю, доступность без упрощения |
| albedil-sbornik | Научная предметность с тёплой интонацией дара |
| tronsky-readings | Плотная источниковедческая работа без публицистики |

Заполнить в `DEFAULT_CONFIG['main_intonation']`, перезапустить пайплайн.

## Новый автор или жанр

### Как добавить автора, которого ещё нет в репозитории?

1. Собрать корпус (минимум 100 единиц одного жанра)
2. Запустить пайплайн:
   ```bash
   python3 rws_pipeline.py txt corpus.txt новый-жанр "Имя Автора"
   ```
3. Проверить `_rules.md` вручную
4. Написать `ClaudeStyles/<handle>-style.md` (вручную, с опорой на `_dh_section.md`)
5. Разместить `.yml` в `styles/passports/`
6. Отправить PR

---

### Как настроить `DEFAULT_CONFIG` под нового автора?

Минимум шесть вещей:

```python
DEFAULT_CONFIG = {
    'genre': 'statya',              # из GENRE_TYPES в скрипте
    'main_intonation': '',          # заполнить после чтения корпуса
    'personal_kw': [...],           # слова личных тем (семья, здоровье, быт)
    'work_kw': [...],               # ключевые термины поля
    'l2_pattern': r'(?!)',          # regex второго языка (или r'(?!)' если нет)
    'manual_limits': [...],         # из раздела «Что исключать» в _style.md
}
```

И отдельно — до запуска:
```python
EPISTEMIC['ironic_cite'] = ['формула1', 'формула2']  # иронические маркеры автора
```

### Как подобрать `l2_pattern` для другого языка?

```python
# Латышский (Гасунс)
l2_pattern = r'[āēīūžčšģķļņŗ]'

# Французский (Мельчук)
l2_pattern = r'[àâçéèêëîïôùûüÿ]'

# Немецкий (умляуты)
l2_pattern = r'[äöüÄÖÜß]'

# Армянский алфавит
l2_pattern = r'[\u0530-\u058F]'

# Грузинский алфавит
l2_pattern = r'[\u10A0-\u10FF]'

# Деванагари (санскрит)
l2_pattern = r'[\u0900-\u097F]'

# Нет второго языка
l2_pattern = r'(?!)'
```

## Несколько жанров одного автора

### Почему у Зализняка 8 стилей?

Потому что «Грамматический очерк» и «Заметки о псевдолингвистике» — разные жанры с разными задачами, разными читателями и разными интонациями. Один корпус даёт один профиль.

Правило: **один жанрово однородный корпус = один прогон = один handle**.

### Как назвать handle для нескольких жанров одного автора?

Конвенция репозитория: `[фамилия]-[жанр]`

```
zalizniak-ocherk
zalizniak-zametki
zalizniak-shkolnikov_1
gasuns-telegram

```

Паспорт при этом один: `styles/passports/zalizniak.yml` — он суммирует все жанры через поле `best_for`.

### Как не смешивать жанры при сборе корпуса?

Перед прогоном отсортировать:

```bash
# Для Telegram: отобрать только анонсы курсов
python3 -c "
import json
data = json.load(open('result.json'))
work_kw = ['курс', 'занятие', 'набор', 'вебинар']
texts = []
for m in data['messages']:
    if m.get('type') != 'message': continue
    t = m.get('text', '')
    if isinstance(t, list): t = ''.join(p if isinstance(p,str) else '' for p in t)
    if any(kw in t.lower() for kw in work_kw):
        texts.append({'date': m.get('date',''), 'text': t})
# texts — только рабочие посты
"

# Для файлов: разбить по папкам жанров
mkdir -p corpus/ocherk corpus/zametki corpus/populyarno
mv *_ocherk*.txt corpus/ocherk/
# затем запускать пайплайн по папке
```

## Проверка статьи или текста

### Как проверить чужую статью на соответствие стилю?

```bash
# Шаг 1: txt
python3 -c "
from docx import Document
open('a.txt','w',encoding='utf-8').write(
    '\n\n'.join(p.text for p in Document('article.docx').paragraphs if p.text.strip()))
"

# Шаг 2: стилометрия
python3 rws_pipeline.py txt a.txt check-tronsky "Автор"

# Шаг 3: качественная проверка через Claude API
python3 check.py ClaudeStyles/tronsky-readings-style.md a.txt
```

`check.py` — вспомогательный скрипт:

```python
import anthropic, sys
style   = open(sys.argv[1], encoding='utf-8').read()
article = open(sys.argv[2], encoding='utf-8').read()
client  = anthropic.Anthropic()
msg = client.messages.create(
    model="claude-sonnet-4-20250514", max_tokens=2000,
    system=style,
    messages=[{"role":"user","content":
        f"Проверь статью на соответствие стилю. Дай разбор:\n"
        f"✅ Что соответствует\n⚠️ Замечания\n❌ Нарушения\n\nСтатья:\n{article[:8000]}"}])
print(msg.content[0].text)
```

### Что значат флаги ✅ ⚠️ ❌ в отчёте Claude?

| Флаг | Значение | Действие |
|---|---|---|
| ✅ | Место соответствует стилю | Ничего |
| ⚠️ | Стиль теряется, но не нарушен | Рассмотреть правку |
| ❌ | Явное нарушение требований жанра | Исправить перед подачей |

---

### Статья уже готова. Стоит ли её переписывать под стиль?

Не обязательно. Стилометрический отчёт — диагностика, не приговор.

Полезно обратить внимание на:
- **H/A < 0.5** + спорные утверждения → добавить «по всей видимости» в конкретных местах
- **Keyness: недопредставлены слова поля** → проверить, не заменены ли термины перифразами
- **Claude: ❌** → это конкретные цитаты, требующие правки

Не нужно менять:
- Низкий hypo/para (если это авторский синтаксис)
- Ассертивность (если аргументы надёжны)

## Паспорта и AI Council

### Чем паспорт `.yml` отличается от `_style.md`?

`_style.md` — дескриптивный документ для человека: что характерно, примеры, формулы, что исключать. Читает человек или LLM как системный промпт.

`.yml` — прескриптивная конфигурация для агента: `checks`, `limits`, `prompt_rules`, роль в совете, приоритет. Читает система.

Связь: каждое правило в `.yml` трассируется к измерению в `_stylometry.md` через поле `source`.

---

### Что такое `conflict_priority` в паспорте?

Приоритет агента в AI Council при конфликте с другим агентом.

Вычисляется из G² топ-1 слова кейнесса:

| G² | priority |
|---|---|
| > 2000 | extreme (агент незаменим, у другого этого голоса нет) |
| 800–2000 | high |
| 300–800 | medium |
| < 300 | low |

Гасунс: `extreme` (санскрит G²=2684). Мельчук: `extreme` (МТТ).

---

### Что такое `can_reply_to` в паспорте?

Домены, в которых агент может возражать другим агентам в совете.

Примеры:
```yaml
can_reply_to:
  - sanskrit_terminology     # Гасунс
  - slavic_linguistics       # Гасунс
  - semantics                # Мельчук
  - syntax                   # Мельчук
  - indology                 # Гасунс-статья
```

Выбирать из топ-3 доменов кейнесса автора.

### Нужен ли один паспорт или несколько на автора?

## Интеграция с НКРЯ

### Зачем нужна интеграция с НКРЯ, если есть встроенный REF_IPM?

Встроенный `REF_IPM` — приближение 2009 года из словаря Ляшевской–Шарова. Он не знает:
- Текущих частот в блогах (подкорпус появился позже)
- Частот узкоспециальных терминов поля
- Региональных или диалектных слов

Для точного кейнесса: скачать частотный список нужного подкорпуса с ruscorpora.ru и подставить в `REF_IPM`.

---

### Как скачать частотный словарь подкорпуса?

На ruscorpora.ru:  
`Портрет подкорпуса → настроить жанр (публицистика / блоги / художественная) → Частотный словарь (CSV)`

Загрузить в скрипт:
```python
import csv
REF_IPM = {}
with open('freq_subcorp.csv', encoding='utf-8') as f:
    for row in csv.DictReader(f):
        REF_IPM[row['lemma']] = float(row['ipm'])
```

---

### Как верифицировать нестандартную конструкцию через НКРЯ?

Открыть [ruscorpora.ru/search](https://ruscorpora.ru/search) и ввести CQL-запрос.

Примеры для Гасунса:

```
# «N лет тому назад» (архаичная форма)
[word="[0-9]+"] [lemma="год"] [word="тому"] [word="назад"]

# «всеравно» слитно
[word="всеравно"]

# «кто» + глагол во множественном числе
[lemma="кто"] []{0,5} [tag="V.*pl.*"]
```

Если конструкция встречается < 50 раз на миллион — нестандартная, фиксируется в портрете как L2-маркер или идиолектная черта.

Значит в одном из `label` правила есть символ `:`, `"` или `{` без экранирования.  
YAML их воспринимает как синтаксис.

Исправить в `manual_limits` / `manual_checks`:
```python
# ❌ Плохо
'manual_limits': ['Не использовать "шикарный"']

# или
'manual_limits': ['Не использовать «шикарный»']
```

## Проверка требований журнала

### Как проверить статью на соответствие требованиям конкретного журнала?

В скрипте есть функция `journal_check()`. Сначала подготовить данные вручную (аннотацию, ключевые слова, заголовки разделов, число источников), затем:

```python
from rws_pipeline import load_txt, journal_check, print_journal_report

texts = load_txt('article.txt')

result = journal_check(
    texts,
    journal       = 'spbu_psychology',   # Вестник СПбГУ. Психология
    article_type  = 'empirical',          # 'empirical' или 'theoretical'
    abstract_text = open('abstract.txt').read(),
    keywords      = ['комментарий', 'перевод', 'корпус', 'санскрит', 'типология'],
    section_headers = ['Введение', 'Методы', 'Результаты',
                       'Обсуждение', 'Выводы', 'Ограничения'],
    source_count  = 18,
    has_references_apa = False,  # есть ли блок References (APA)?
)
print_journal_report(result)
```

Вывод:
```
════════════════════════════════════════════════════════════
Журнал: Вестник СПбГУ. Психология
✅ 8 выполнено  ⚠️ 1 предупреждений  ❌ 3 нарушений
────────────────────────────────────────────────────────────
❌ Нарушения:
  Объём велик: 40,782 знаков (максимум 38,000)
  Аннотация: 22 слов (норма 230–250)
  Отсутствует блок References (APA)
⚠️  Предупреждения:
  Аббревиатуры без расшифровки: ['ИМЛИ', 'СССР'] — проверить
```

---

### Какие требования Вестника СПбГУ. Психология проверяются автоматически?

| Требование | Источник | Как проверяется |
|---|---|---|
| Объём 20 000–38 000 знаков | §1 требований | `len(text)` |
| Аннотация 230–250 слов | §3 | `len(abstract.split())` |
| Аннотация — единый абзац | §3.2 | поиск `

` в abstract_text |
| В аннотации нет списков | §3.3 | regex `^[•\-\*\d]+[\.\)]` |
| В аннотации нет ссылок | §3.4 | regex `\(\w+,\s*\d{4}\)` |
| Ключевых слов 5–7 | §4.1 | `len(keywords)` |
| Структура (все разделы) | образец | сравнение с required_sections |
| Два списка (ГОСТ + APA) | §8 | поиск «Литература» + «References» |
| Двуязычные метаданные | образец | наличие латинского блока |
| Аббревиатуры с расшифровкой | §7.6 | heuristic по CAPS без скобок |
| Иностранные авторы в скобках | §7.5 | (проверяется частично) |
| Анонимные источники — в сноски | §8.2 | предупреждение в rules.md |

---

### Какие требования нельзя проверить автоматически?

- **Содержание аннотации** (Background / Objective / Design / Results / Conclusion) — только вручную
- **Качество перевода в References** — только вручную
- **Транслитерация по Library of Congress** — проверить на [translit.ru/lc](https://translit.ru/lc)
- **Разрешение рисунков 300 dpi** — только через EXIF
- **Порядок авторов** (вклад или алфавит) — только авторы знают
- **Актуальность источников** (последние 5 лет) — подсчёт по годам возможен, но требует парсинга списка

### Как добавить требования другого журнала?

В `rws_pipeline.py` найти словарь `JOURNAL_PROFILES` и добавить новый профиль:

```python
JOURNAL_PROFILES['voprosy_yazykoznaniya'] = {
    "name": "Вопросы языкознания",
    "chars_min": 25_000,
    "chars_max": 60_000,
    "abstract_words_min": 200,
    "abstract_words_max": 300,
    "keywords_min": 5,
    "keywords_max": 10,
    "sources_empirical_min": 20,
    "sources_theoretical_min": 50,
    "bilingual_required": True,
    "two_bibliographies": True,
    "citation_style_ru": "ГОСТ",
    "citation_style_en": "APA",
    # ... остальные поля
}
```

Затем: `journal_check(texts, journal='voprosy_yazykoznaniya', ...)`.

---

### Что означает флаг ❌ «Отсутствует блок References (APA)»?

Вестник СПбГУ требует **два отдельных списка**:

1. **Литература** — по ГОСТ, русскоязычные источники первыми:
   ```
   Падучева Е. В. Высказывание и его соотнесённость с действительностью. М.: Наука, 1985.
   ```

2. **References** — по APA, русскоязычные с транслитерацией по Library of Congress:
   ```
   Paducheva, E. V. (1985). Vyskazyvanie i ego sootnesennost' s deistvitel'nost'iu.
   Nauka. (In Russian)
   ```

Скрипт проверяет наличие заголовка «References» в тексте. Если его нет — нарушение.

---

### Как привести транслитерацию в соответствие с Library of Congress?

Сайт: [translit.ru/lc](https://translit.ru/lc)  
Или: [convertcyrillic.com](http://www.convertcyrillic.com/#/convert) → ALA-LC without Diacritics.

Пример:
```
Падучева → Paducheva
Высказывание → Vyskazyvanie
Наука → Nauka Publ.
Вопросы языкознания → Voprosy iazykoznaniia
```

Названия издательств: `Piter Publ.`, `Smysl Publ.`, `Nauka Publ.` — **без перевода**, только транслитерация.

## Теоретическая подоплека

### На каком теоретическом основании построен пайплайн?

На двух столпах московской лингвистической семантики — **Апресяне** и **Падучевой** — но не как объектах изучения, а как метатеоретическом уровне. Подробно в [`THEORY.md`](THEORY.md). Коротко:

**Апресян** (интегральное описание, лексические функции, картина мира) объясняет:
- Почему кейнесс работает: сигнатурные слова маркируют семантическое поле идиолекта
- Почему номинализация диагностична: трансформация событие→объект меняет прагматический вес
- Почему недопредставленные слова важны: «человек», «жизнь» — концепты «наивной картины мира»; их отсутствие = специализированный идиолект
- Почему матрица трансляции осмысленна: это обратная МТТ (Модель «Смысл ↔ Текст»)

**Падучева** (высказывание, точка зрения, модальность) объясняет:
- Почему эпистемическая модальность — отдельный модуль: её типология (эпистемическая, эвиденциальная, деонтическая) прямо отображается на наши категории
- Почему `ironic_cite` — не хеджирование: это несобственно-прямая речь, дистанцирование от чужого слова
- Почему hypo/para важен: паратаксис оставляет пропозициональные связи имплицитными; это выбор, а не случайность
- Что такое `main_intonation` технически: «точка зрения» нарратора в её терминах

## Вклад в проект

### Как правильно добавить нового автора в репозиторий?

```
1. Собрать корпус (жанрово однородный, ≥ 100 единиц)
2. python3 rws_pipeline.py <mode> <file> <handle> "Автор"
3. Проверить _rules.md вручную
4. Написать ClaudeStyles/<handle>-style.md
5. Добавить main_intonation в .yml
6. git add ClaudeStyles/<handle>* styles/passports/<автор>.yml
7. git commit -m "Add style: <handle>"
8. git push → Pull Request
```

### Нужно ли отправлять исходный корпус в PR?

Нет — только финальные файлы (`_style.md`, `.yml`). Корпус может быть приватным.

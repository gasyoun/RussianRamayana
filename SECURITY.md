# Security

«Русская Рамаяна» — статический сайт (GitHub Pages): нет сервера, нет базы
данных, нет приёма пользовательского ввода на хранение. Поверхность атаки
минимальна. Ниже — модель угроз и известные ограничения.

## Модель и текущее состояние

- **XSS.** Все данные перед вставкой в DOM экранируются `esc()` (экранирует
  `& < > "`), а все ссылки/источники пропускаются через `safeUrl()`, который
  пропускает только `https:` (блокирует `javascript:`/`data:`). Внешние ссылки
  открываются с `rel="noopener noreferrer"`. Данные ведутся в репозитории
  (правка = доступ к репозиторию), так что это эшелонированная защита.
- **Секреты.** В репозитории нет секретов. Донорские данные
  (`donations_private.csv`, `_private/`) — в `.gitignore` и не коммитятся.
- **Зависимости.** Рантайм-зависимость одна — Leaflet с CDN (с SRI-практикой
  по возможности). Сборка (`prerender.py`) использует Playwright только в CI.

## Известное ограничение: «калитка» черновиков (drafts.html)

Парольная форма на [drafts.html](drafts.html) — **только удобство интерфейса,
а не контроль доступа.** На статическом сайте:

1. `data/drafts.json` доступен по прямой ссылке независимо от формы;
2. SHA-256-хеш пароля виден в исходнике (без соли, перебираем офлайн);
3. при `PLACEHOLDER_HASH` форма открывается любым непустым вводом.

**Правило:** в `data/drafts.json` допустимы только публично-безопасные тизеры.
Подлинно приватные подписочные материалы должны храниться за настоящей
авторизацией платформы подписки, а не на этом сайте. На текущий момент
содержимое `drafts.json` — заглушки, реальный текст не раскрыт.

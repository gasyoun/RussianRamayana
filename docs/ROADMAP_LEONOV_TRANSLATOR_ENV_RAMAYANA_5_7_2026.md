# Среда переводчика Рамаяны (книги 5–7): автосноски по трудным словам — роадмап

_Created: 12-07-2026 · Last updated: 12-07-2026_

Авторство аудита и роадмапа: Fable 5 (`claude-fable-5`), рулинги — М. Гасунс (интервью 12-07-2026).

## 1. Задача

Процесс М.В. Леонова сегодня: прочитать шлоку → уточнить неясное по словарям и комментариям → перевести → править до литературной удовлетворительности. Когда слово не имеет четкого русского эквивалента (пример: kālāntaka — Гринцер «поглотитель времени», Кальянов «всеразрушитель»/«всеистребляющая смерть», Васильков «Несущий смерть»/«пресекающий срок»), он вручную гоняет «Пахтанье океана» — 499 запросов с 2023 года, включая не только Рамаяну, но и «Жизнь Будды» и другие его переводы.

Цель среды: к каждой шлоке книг 5 (Сундара), 6 (Юддха), 7 (Уттара) трудные слова показываются **сразу, сноской**, с аттестованными передачами классиков и словарными глоссами — ручной запрос и сверка глазами исчезают из цикла.

## 3. Принятые решения (интервью 12-07-2026)

1. **Форма поставки: все три** — статичные HTML-листы по саргам, .docx в его Word-workflow, режим в samskrtam.ru. После пилота Леонов сам скажет, что удобнее; тогда две формы уходят в поддержку по остаточному принципу.
2. **Текст книг 6–7:** частично valmiki.iitk.ac.in (Gita Supersite), частично GRETIL (sa_rAmAyaNa TEI) + правка по книге (сверка с печатным изданием Леонова).
3. **Отбор слов — все четыре сигнала:** (а) расхождение классиков в аттестованных передачах; (б) редкость слова в корпусе; (в) лог его 499 запросов (после экспорта); (г) слова без устоявшегося эквивалента в его СОБСТВЕННЫХ переводах. Селф-TM строится из всех переводов Леонова: Сундара (книга 5), Бхартрихари 2020, **Буддхачарита и Амару** (тоже его переводы — уточнение МГ).
4. **Содержимое сноски: детерминированный список с locus** («Гринцер: … (Рам. …); Кальянов: … (МБх 1950 I:632); Кочергина: …») — ноль генерации, полная проверяемость. **DeepSeek-синтез абзаца — пробно на первых 5** (пилотная партия), дальше по результату; Anthropic-ключ не используется (правило репо), LLM = DeepSeek через openai-совместимый бекенд.

### Wave 0 — Пилот на книге 5 (сарги 1–2) — [H764](https://github.com/gasyoun/Uprava/blob/main/handoffs/archive/H764-Opus_RussianRamayana_translator-env-pilot-sundara_12.07.26.md)

Книга 5 выбрана для пилота не потому, что нужна Леонову (перевод завершен), а потому, что только там есть валидационная база — его собственный ручной аппарат.

1. Движок трудности: по каждой шлоке — SLP1-леммы → 4 сигнала из §3.3 → ранжированный список кандидатов на сноску.
2. Генератор сносок: детерминированный список передач с locus + словарные глоссы.
3. **Валидация против ручного аппарата сарги 1:** какие из 628 словарных строк прототипа движок воспроизводит/покрывает (recall), сколько лишнего добавляет (precision-подобная оценка). Отчет — таблицей в этот репо.
4. Выпуск сарг 1–2 в трех формах: автономный HTML-лист, .docx (сноски настоящими footnotes), мок веб-режима.
5. DeepSeek-синтез абзаца — на первых 5 единицах пилота, помечен как машинный.
6. Передать Леонову → его выбор формы + отзыв по шуму/пропускам фильтра.

Выход: точность отбора известна, форма выбрана. Стоп-условие пилота — в H764.

## 5. Не-цели

- **Не** строить пословное выравнивание заново — `corpus_lexicon.jsonl` существует (84,4% точности); пробелы лечатся точечно (H309), не пересборкой.
- **Не** брать критическое издание Baroda как базовый текст — Леонов переводит южную рецензию; для книги 5 разница составила +371 шлоку и 2 отсутствующие сарги, нумерация разошлась бы системно.
- **Не** публиковать сгенерированные листы публично: сноски цитируют Кочергину (1987) и современные переводы под копирайтом. Листы — приватный рабочий инструмент переводчика; любой шаг к публикации — через /publish-safety-check.
- **Не** дублировать корпус SamudraManthanam в другие репо — запрашивать (архитектурное правило проекта).
- **Не** редактировать тексты Леонова — среда добавляет сноски, никогда не трогает его перевод (правило аппарата CommentaryStrategies действует и здесь).

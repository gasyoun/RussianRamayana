# DCS параллельные пассажи → слой контекста для сносок переводчика

_Created: 15-09-2026 · Last updated: 15-09-2026_

H4706 (OxAlpha): датасет kosha **`dcs-parallel-passages-full`** потреблён как
per-passage контекст для auto-footnote листов translator-env (/translator-env).

## Что построено

| Артефакт | Что это |
|---|---|
| `translator-env/src/build_dcs_parallels.py` | детерминированный сборщик слоя (dry-run по умолчанию, `--emit` / `--check`) |
| `translator-env/data/dcs_parallels.tsv.gz` | слой: 167 строк — все выравнивания Рамаяны в экспорте, обе стороны |
| `translator-env/data/dcs_parallels_sundara_s01_s02.json` | срез под пилотные листы (сарги 1–2 Сундары), формат для gen_sheets |

Слой перегенерируется идентично: gzip пишется с mtime=0 (контейнер
воспроизводим байт-в-байт), `--check` сверяет контент после распаковки:
`python translator-env/src/build_dcs_parallels.py --check` → `CHECK PASS`.

## Метод

Вход — выгрузка PARA/Polnorazmernye (245 файлов, по файлу на текст-источник;
строка = `<метка>`;`адрес`;`санскрит`;<парал-ref>`;`парал-текст`;`verdict`;`дельта`).
Рамаяна (DCS text 248, `Rām, K, S: …`) участвует двумя путями: своим файлом
`248_1--606.csv` (≈37 тыс. полушилок-источников, 132 выравнивания после
дедупа) и как цель в ~11 чужих файлах (35 после дедупа; в основном МБх).

Числовые метки DCS внутренне непоследовательны (`Rām, 5, 1: 325` + адрес
`1 1` = Сундара 1.1, но также `Rām, 1, 1: 1` + адрес `76 2`), поэтому
адресация строится **по тексту**: каждая сторона ищется в корпусе
SamudraManthanam (индекс: вся шлока + каждый данд-кусок + пары соседних
кусков, норма без диакритики только для поиска; в слое тексты дословны).
Сторона Рамаяны локуется только в кандах Рамаяны, чужая — в МБх с фолбэком
в Рамаяну (внутрирамаянские параллели). Данные читаются по пути из
`../VisualDCS` — в репозиторий копируется только производный слой.

## Числа

- сырых выравниваний с участием Рамаяны: **240** (после дедупа текстовых пар — **167**)
- вердикты экспорта: GOOD **64**, PARTLY **103**
- сторона Рамаяны локована в корпус: **85/167** строк (51%); чужая сторона: **88/167** (53%)
- по кандам (локованные): Сундара **56**, Айодхья **12**, Бала **4**, Юддха **6**, Уттара **5**, Аранья **2**
- пилотный срез (Сундара 1–2): **4** пассажа — 1.155, 1.156, 2.39, 2.40

## Главная находка (честное дно)

**dcs-parallel-passages-full почти не содержит параллелей Рамаяны.** 240
выравниваний на ~19 тыс. шлок — плотность выгрузки живёт в
буддийско-эпических формулах (Divyāvadāna↔МБх и т.п.), не в Рамаяне. Как
per-passage контекст для сносок слой полезен точечно (Сундара 28–66:
Rāvaṇa-Sītā диалоги, 56 строк), но не сплошно. Для сплошной покрышки нужен
либо стоп-словный вариант (PARA/Stopovye, не диффован), либо конкорданс B3
(`parallel-passage-concordance`, 13,862 GOOD + 139,183 PARTLY по всему DCS —
производное той же выгрузки, уже инвертированное) — отдельное решение.

## Проверка (20-строчная ручная выборка)

Случайная фикс. выборка seed=4706, 20 строк слоя: обе стороны каждой строки
найдены **дословно** в сырой выгрузке VisualDCS — **20/20 EXPORT-PARITY**.
Локованные строки выборки перепроверены адресно по корпусу (passage = текст).
Прямой заход на живой DCS (JS-приложение sanskritdictionary.com/dcs) не
использовался — экспорт и есть зарегистрированное DCS-содержимое (kosha
`dcs-parallel-passages-full`, CC BY-SA 4.0); в отчёте это отмечено как
ограничение проверки, не как замалчивание.

Ограничения: (а) ~49% сторон не локуются — корпус SamudraManthanam покрывает
не все шлоки/ редакционные разночтения DCS (кишкиндха-файла в корпусе нет
вовсе), такие строки несут сырую ссылку DCS без координат корпуса;
(б) лока — точная текстовая, без фаззи-сандхи, часть PARTLY-вариантов этим
недоловлена.

## Путь в kosha (расхождение с формулировкой миссии)

Миссия называла вход «kosha data/parallel_passages export»; в kosha/data
такого каталога нет. Зарегистрированный источник датасета —
`VisualDCS/derived-data/Paralleli-v-tekstah-korpusa-SRC/PARA/Polnorazmernye/`
(manifest: source_repo github.com/gasyoun/VisualDCS), оттуда и читаем.

## Как генерировать листы со слоем (для gen_sheets)

Пилотный JSON: `{passage: [{ram_text, label, work, passage, ref_raw, text,
verdict, delta, direction}]}` — сноске уровня пассажа достаточно: label +
passage (локовано) или ref_raw (нет), text, verdict. Подключение — один
источник данных в `gen_sheets.py`, без изменений ядра.

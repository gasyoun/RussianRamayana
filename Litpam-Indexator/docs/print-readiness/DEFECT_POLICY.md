# DEFECT_POLICY — классы дефектов, default-диспозиции и правила записи

## 1. Классы

### blocker — печать невозможна / данные теряются

Правится ДО продолжения производственной цепочки; работа над независимыми
проверками продолжается (рулинг 24 — это не stop-условие, кроме перечисленных там).

- overset (вытесненный текст) в любом фрейме указателя;
- clipping: обрез текста краем фрейма/полосы, текст в небезопасной зоне обреза;
- потеря словарной статьи или локатора против словника (рулинг 29 — никакая
  молчаливая потеря недопустима);
- битая ссылка: локатор вне диапазона полос тома; «см.» на несуществующую статью;
- missing glyph / подмена гарнитуры;
- corruption файла, отсутствующий обязательный asset/font (это же — stop-условие
  рулинга 24).

### material — печать возможна, но издательское качество нарушено заметно

Правится в текущей волне (рулинг 16: «существенно отвлекающие»).

- orphan: заголовочное слово оторвано от своих локаторов/подстатей границей
  колонки или полосы; одиночная оборотная строка на новой колонке;
- неверный recto/verso против контракта (§5–§6 spec);
- ненамеренная пустая полоса; колонтитул/колонцифра там, где контракт требует
  спуск, и наоборот;
- recto-колонтитул называет не тот указатель;
- нарушение сетки отступов (строка вне четырёх координат §4);
- утечка символьного стиля (пример — D7 spec: полужирная первая литера);
- полужирность локатора не соответствует семантике примечаний (§7.3);
- нарушение алфавитной сортировки статей; дубль статьи (кроме законных омонимов
  с глоссами);
- межтомное расхождение мебели (furniture) вне записанных exceptions §11 spec.

### cosmetic — заметно при вычитке, печать не порочит

В очередь (рулинг 16); чинится попутно при регенерации, отдельная сессия под них
не открывается.

- regular-тире внутри полужирного диапазона (D9);
- двойные/лишние пробелы (D10), несогласованная отбивка после «см.»;
- неудачная разбивка заголовка указателя на строки (D2);
- вынужденные переносы, которые допустимы, но некрасивы;
- микроразнобой трекинга/интерлиньяжа, не ломающий сетку.

## 2. Default-диспозиции (рулинг 23)

| Ситуация | Default | Куда записывается |
|---|---|---|
| Обратимая неоднозначность оформления | применить отмеченный default из §11 spec, продолжать | `decision-log.md` рядом с ledger |
| Смысловой/редакционный fork (текст глоссы, унификация «см.», слияние статей) | НЕ решать молча; статус `WAITING` | defect ledger, строка WAITING |
| Необратимое действие (правка вне версионных копий, production binaries) | запрещено политикой; не выполняется | — (fence, рулинг 26) |
| Автотест FAIL | дефект в ledger, артефакты сохраняются, независимая работа продолжается | ledger |
| Регенерация расходится с печатью 2025 | печать 2025 — визуально-редакционная база (рулинг 4), но контракт+словник главнее; расхождение в отчёт сравнения | отчёт сравнения + ledger при дефекте |

Класс по умолчанию при сомнении между двумя классами — **более тяжёлый** (дешевле
понизить при триаже, чем пропустить blocker).

## 3. Формат записи

Ledger — JSON + MD-зеркало в
`Litpam-Indexator/artifacts/print-readiness/<scope>/defect-ledger.json`
(схема полей — `defect_ledger` в
[config/print-readiness.json](https://github.com/gasyoun/RussianRamayana/blob/main/Litpam-Indexator/config/print-readiness.json)).
Обязательные поля строки:

| Поле | Содержание |
|---|---|
| `id` | `DFT-<том>-<порядковый>`, например `DFT-I-0001`; append-only, не переиспользуется |
| `class` | `blocker` / `material` / `cosmetic` |
| `status` | `open` / `fixed` / `queued` / `WAITING` / `wontfix-exception` |
| `volume`, `index`, `page` | том (I/II), указатель (1–4 по порядку §5 spec), полоса |
| `rule` | пункт spec, который нарушен (например `§7.3`) |
| `observed` / `expected` | что видно / что требует контракт — дословно, без оценок |
| `disposition` | применённый default или требуемое решение; для `WAITING` — какой человеческий акт нужен |
| `evidence` | путь к рендеру/отчёту в artifacts |
| `found_by` | инструмент или чек-лист + tier и точная версия модели |

Правила ведения:

1. **Каждый** осмотренный кандидат получает строку — включая вердикт «не дефект»
   (`wontfix-exception` со ссылкой на §11 spec). Осмотр без записи = осмотра не было.
2. Ledger append-only по `id`; правки только полем `status`.
3. `WAITING`-строки зеркалируются в
   [Uprava GTD](https://github.com/gasyoun/Uprava/blob/main/GTD_NEXT_ACTIONS.md)
   как `@DECIDE`/`@WAITING` той же сессией, что их создала.
4. Дефект против УЖЕ записанного exception (§11 spec) дефектом не является —
   ссылка на exception обязательна.

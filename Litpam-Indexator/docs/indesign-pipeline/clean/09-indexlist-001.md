Готовим первую таблицу указателя.

**Стартовый набор стилей.** В папке `Info` есть подпапка «Стили индекса (Index styles)» со стартовым файлом, где уже задан начальный набор стилей для таблицы `IndexList`. Для удобства в учебной папке есть готовый файл `IndexList` (с нумерацией строк), где эти стили уже есть, — с него и начинаем. По `Shift+F11` (символьные стили) видно группу «Index styles»: пять стилей уровней и один стиль-разделитель.

**Данные из словаря.** Открываем `.xlsx`, начинаем с именного указателя. Берём колонку(и) с текстом вариантов: через точку с запятой перечислены формы, которые предполагается встретить в тексте.

> Ключевая особенность для «Рамаяны»: здесь **не** запускается мой анализатор словоформ (который сам предполагает возможные варианты) — все варианты берутся буквально из столбца. Если форма указана один раз — ищется только она. Это сильное решение: если есть разметчик (Анатолий), который перечислил все варианты, лучшего входа и не надо.

1. Копируем текст из `.xlsx`, вставляем в вёрстку — получаем две колонки. К вставке цепляются пустые строки — их надо сразу удалить, иначе скрипт не отработает (он и сам об этом предупредит).
2. Запускаем подготовку таблицы. Для «Рамаяны» используется именно `UseReadyTable.v.7.jsx` (для других проектов — другая версия).

Скрипт делает шесть проходов с разными задачами (в т. ч. чистку текста: сдвоенные пробелы, лишние табуляции). Что в результате видно в таблице:

- **Колонка-флаг:** если во второй колонке стоит буква `n` (и пункт пуст) — строка обрабатываться не будет (способ исключить строку). Иначе должен стоять `#` (решётка) или номер.
- **Регистр:** перед словом ставится `-I` или `-i`. `-I` — искать слово только с прописной буквы (как написано); `-i` — искать и со строчной, и с прописной. Так снимается проблема регистра.
- **Сортировка по длине:** формы одного термина скрипт сортирует по убыванию длины (например, «супруг» ← «супруга» ← «супруги»), чтобы находилось слово целиком, а не его кусок. Поиск идёт по границам слова.
- **Колонка стилей (предпоследняя):** сюда попадут все символьные стили, уже созданные в вёрстке при теговой разметке. Позже, при сборке сводного `IndexList`, мы перетащим индексы на правильные места из того файла.

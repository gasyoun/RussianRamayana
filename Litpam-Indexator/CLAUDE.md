# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Не программный проект, а рабочий комплект для построения предметных указателей к двухтомнику «Рамаяна» в Adobe InDesign. Основа — набор ExtendScript-скриптов (.jsx) Михаила Иванюшина (dotextok.ru), сгруппированных по этапам конвейера, плюс вспомогательная Windows-утилита на Free Pascal. Язык документации, комментариев и диалогов — русский.

## Запуск и проверка кода

Здесь нет сборки, линтера и тестов в обычном смысле.

- **.jsx-скрипты выполняются только внутри InDesign** (палитра Window → Utilities → Scripts). Автономно их не запустить; функциональная проверка — прогон на учебном примере `#Indexing. Ramayana/Info/Учебные примеры (Drill examples)/Golden Fish Story/`.
- **Статическая проверка синтаксиса** возможна через Node: снять BOM и препроцессорные директивы (`#include`, `#targetengine`), затем `node --check`. Учесть: ExtendScript — это ES3-диалект, допускающий `};` перед `else` и `if (a) f() else g()` в одну строку. Такие места в коде — НЕ ошибки, не «исправлять» их.
- **Утилита `_Ram_Tag_explorer/teg_exp.exe`** собирается из исходников Lazarus (`teg_exp.lpi`): `lazbuild teg_exp.lpi`. Требует Windows и установленный Excel (читает xlsx через OLE).

## Конвейер (big picture)

Данные движутся так:

```
Tags/ram_tags.txt        xls/Указатель_к_Рамаяне_*.xlsx
(текст с разметкой         (словник: 4 листа = 4 указателя,
 #термин{Тег\уровень})      падежные формы через «;»)
        │                          │
        │  ← teg_exp.exe сверяет их между собой (до InDesign)
        ▼                          ▼
[0] FindTags: перенос разметки → символьные стили в вёрстке (InDesign/Ramayana_*.indd)
[1] UseReadyTable → таблицы IndexList-nnn.indd → AddMarker (буква указателя)
    → MergeTwoIndexListTables → сводный IndexList[@]nnn.indd
[2] Проверка таблиц (для Рамаяны почти не нужна — дубликатов grep-запросов нет)
[3] ProcStoryOrDoс: по строкам IndexList расставляет index-маркеры в вёрстке
    → генерация указателя стандартными средствами InDesign
[4] Оформление: свёртка номеров страниц → ссылки «См.» → скрытие служебных
    номеров → алфавитные рубрики (очерёдность — в «Очерёдность.txt»)
```

Папки `[0]`–`[4]` в `#Indexing. Ramayana/` соответствуют этапам; в каждой есть `info.txt` с пояснениями автора. Пошаговый план работ — `Roadmap_Ramayana_Index-Vol.1.md` в корне.

## Общий контракт: ForIndex.jsxinc

Почти каждый скрипт начинается с `#include "../ForIndex.jsxinc"` (глубина `../` или `../../` — строго по вложенности папки; это частый источник ошибок). Файл задаёт жёсткие имена, на которые завязана вся система — **не переименовывать** ни в коде, ни в документах InDesign:

- абзацные стили уровней `#Level1`…`#Level4` (группа `#IndexStyles`) и стили оформления `#Level1=Index`…;
- цвета: `SkipTheWord` (слово запрещено индексировать), `IndexColor`/`usedColor` (уже обработано), `IndexStylesColor`;
- маркер отсутствующего уровня — длинное тире (`noLevel`);
- схема имён файлов таблиц: `IndexList-nnn.indd` (без маркера) / `IndexList[X]nnn.indd` (X — латинская буква указателя) / сводный `IndexList[@]nnn.indd`.

## Ловушки

- В имени файла `[3. Индексирование]/ProcStoryOrDoс[09.10.2023].jsx` буква «с» в «Doс» — **кириллическая**. Учитывать при поиске/сопоставлении по имени.
- Кодировки: .jsx — UTF-8 с BOM, CRLF (сохранять именно так); некоторые авторские .txt (`[Индексирование. Программы].txt`, `Очерёдность.txt`) — cp1251.
- Папки `tmp/` внутри этапов — архив черновиков и бэкапов (в т.ч. с битыми include-путями); в рабочий конвейер не входят, не чинить без запроса.
- Скрипты этапов 1 и 3 отказываются работать при вытесненном (overflow) тексте и несохранённом документе — это проверки в коде, а не баги.
- В `xls/` рабочие листы — только «Именной», «Географ», «Предметы и термины», «Флора и фауна» (и справочник «Все_Теги»); остальные листы служебные.
- `_Ram_Tag_explorer/backup/` и `lib/` — артефакты Lazarus, генерируются при сборке.

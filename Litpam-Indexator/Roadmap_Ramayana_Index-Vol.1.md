## Этап П. Подготовка (один раз)

- ☐ **П1. Резервная копия.** Скопируйте `InDesign/Ramayana_I_12.10.25/` целиком (например, в `InDesign/_backup/`). Все дальнейшие шаги делайте на рабочей копии.
- ☐ **П2. Удалите lock-файл** `~ramayana_i_12.10.2~f5jd0f.idlk` из папки тома I (остался от открытого файла). Откройте .indd и убедитесь, что он открывается без ошибок; если нет — восстановите из .idml.
- ☐ **П3. Подключите скрипты в InDesign.** Window → Utilities → Scripts → правый клик на User → Reveal in Explorer → скопируйте туда папку `#Indexing. Ramayana` (или ярлык). Скрипты запускаются двойным кликом из палитры Scripts.
- ☐ **П4. Импортируйте служебные стили.** В верстке тома I: Paragraph Styles → меню → Load Paragraph Styles → выберите `Info/Стили индекса (Index Styles)/IndexStyles.idml` → группа `#IndexStyles` (стили `#Level1`…`#Level4` и `#Level1=Index`…`#Level4=Index`).
- ✋ **Проверка:** в Paragraph Styles видна группа `#IndexStyles`; в Character Styles — группа `Index styles` (появилась после переноса разметки на этапе 0). Если группы `Index styles` нет — этап 0 не завершен, начните с `FindTags.2024.jsx`.
- ☐ **П5. (Рекомендуется) Тренировка на Golden Fish.** Пройдите этапы 1 → 3 → 4 на примере `Info/Учебные примеры (Drill examples)/Golden Fish Story/` — там маленький текст и готовый словник. Это ~час, но сэкономит дни на реальном томе.

## Этап 1. Подготовка таблиц IndexList

Для каждого из четырех указателей (листы xlsx: «Именной», «Географ», «Предметы и термины», «Флора и фауна») повторите шаги 1.1–1.4.

- ☐ **1.1. Перенос словника в InDesign.** Создайте новый документ InDesign, вставьте таблицу-двухколонник:
  - колонка 1 — термин с уровнями через `\` (колонка «Имя» листа xlsx, напр. `Агастья\великий риши`);
  - колонка 2 — падежные формы через `;` (колонка «Что искать, через точку с запятой»).
  Практично: скопируйте обе колонки из Excel → Edit → Paste в текстовый фрейм → выделить текст → Table → Convert Text to Table.
  ⚠ Строки без падежных форм и служебные строки (`=VLOOKUP…`) в таблицу попадать не должны — копируйте только значения нужных двух колонок.
- ☐ **1.2. Сохраните файл** с осмысленным именем (напр. `Slovnik-Imennoy.indd`). Несохраненный файл скрипт попросит сохранить.
- ☐ **1.3. Запуск `[1. Подготовка таблиц]/UseReadyTable.v.7.jsx`.** Курсор — в любую ячейку таблицы. В верстке словника не должно быть вытесненного (overflow) текста.
  Скрипт: разложит синонимы из «;» по строкам, достроит пропущенные уровни (прочерк `—`), соберет grep-запросы и сохранит `IndexList-000.indd`.
- ☐ **1.4. Запуск `AddMarker.jsx`** на полученном IndexList — назначьте указателю латинскую букву-маркер. **Канон — `a`/`b`/`c`/`d`** (`AddMarker` берет буквы из массива `markLetters = ["a","b","c","d",…]` в `ForIndex.jsxinc`): `a` — именной, `b` — географический, `c` — предметы/термины, `d` — флора/фауна. Переименуйте файл по образцу `IndexList[a]001.indd`. _(Мнемоническая схема `N/G/T/F` — лишь удобное для чтения предложение, но код ставит `a/b/c/d`; введение мнемоник = правка `markLetters`, т.е. изменение кодового контракта.)_ Единая привязка «указатель ↔ лист ↔ IndexList ↔ буква» — в [Розеттской таблице MANUAL](https://github.com/gasyoun/RussianRamayana/blob/main/Litpam-Indexator/docs/indesign-pipeline/MANUAL.md#розеттская-таблица-указателей).
- ✋ **Проверка после каждого указателя:** откройте IndexList — в третьей колонке grep-запросы вида `(?i)\b(…)\b`, уровни непрерывны (нет «дыр» 1→3), в конце ячеек нет `;`.
- ☐ **1.5. Объединение.** `MergeTwoIndexListTables.jsx` объединяет два IndexList; повторите три раза: (N+G) → (+T) → (+F). Итог — сводный `IndexList[@]…indd`.
- ✋ **Контрольная точка этапа:** один сводный файл IndexList[@]; число строк ≈ сумма строк четырех таблиц; у каждой строки — буква указателя.

## Этап 2. Проверка таблиц (для Рамаяны — сокращенно)

По info.txt автора, для Рамаяны совпадающих grep-запросов нет, поэтому этап почти пропускается. Минимум:

- ☐ **2.1. Выборочная проверка поиска.** Откройте верстку тома I и IndexList[@]. Курсор в строку термина → `[2…]/ShowFoundByGrep.v.3.jsx` — покажет, что реально находит grep-запрос в тексте. Проверьте 10–20 «сложных» терминов (короткие слова, омонимы, имена с вариантами).
- ☐ **2.2. (Опционально) `TermCompare[+letter].v.2.jsx`** — поиск строк с совпавшими запросами, на случай если словник менялся.
- ⚠ Если запрос находит лишнее (слово входит в другой термин) — пометьте такие слова в тексте цветом `SkipTheWord`, они будут пропущены при индексировании.

## Этап 3. Индексирование (основной этап)

- ☐ **3.1.** Откройте два документа: верстку `Ramayana_I_…indd` и сводный `IndexList[@]`. Еще раз убедитесь: overflow-текста нет, документ сохранен.
- ☐ **3.2. Запуск `[3. Индексирование]/ProcStoryOrDoс[09.10.2023].jsx`.** Скрипт идет по заданиям таблицы и расставляет маркеры указателя рядом с найденными терминами. Обработанные строки таблицы окрашиваются стилем `#ProcessedLines`.
  - Слова цветом `SkipTheWord` — пропускаются;
  - слова цветом `IndexColor` — уже обработаны (защита от повторов);
  - если маркер не удалось поставить — появится лог-файл, все проблемные места перечислены в нем.
- ✋ **Проверка:** лог пуст или разобран; в Index-панели (Window → Type & Tables → Index) появились темы с номерами страниц.
- ☐ **3.3. Чистка ложных срабатываний.** Просматривая текст: выделите фрагмент → `Tell_Index_Item.jsx` покажет, какой термин сюда попал. Ненужные вхождения удаляйте:
  - `DeleteUnnecessarySign [Black].jsx` — просто удалить маркер (при повторном прогоне слово вернется);
  - `DeleteUnnecessarySign [SkipTheWord].jsx` — удалить и запретить навсегда (окрасит `SkipTheWord`).
  Правки терминов в таблице — `GetInfoForSearch.jsx`.
- ☐ **3.4. Генерация указателя.** Index-панель → Generate Index → поместите указатель в конец документа (или отдельный документ книги).
- ✋ **Контрольная точка этапа:** сгенерированный сводный указатель; каждая строка начинается с буквы-маркера (`a`/`b`/`c`/`d`); номера страниц выборочно сверены с текстом.

## Этап 4. Оформление указателя

Очередность — по файлу автора `Очередность.txt`:

- ☐ **4.1. Разделение на четыре указателя.** Отсортированный InDesign-ом сводный указатель разделите по буквам-маркерам на 4 части (буквы в начале строк группируют термины по указателям).
- ☐ **4.2. Номера страниц:** `[Оформление номеров страниц в указателе]/ProcNumberLines[3-4,6-8].jsx` — свертка последовательностей (3,4 → 3-4). Вариант `[3,4,6-8].jsx` — если соседние страницы через запятую. Выбор один раз, применить к каждому указателю.
- ☐ **4.3. Ссылки «См.»:** `[Оформление ссылок 'См']/AddSeeTopic.v.3.v.3.jsx` — добавление перекрестных ссылок. Образец — `Info/…/SeePointer (Ссылка См.)/#TwoLevelSimplestSample.idml`.
- ☐ **4.4. Аннотации (именной указатель).** Подготовьте `AnnotationData.docx` из колонок «Имя» + «Краткая аннотация»/«Описание» листа «Именной» (образец — в `Info/Стили индекса (Index Styles)/AnnotationData.docx`) → `AddAnnotationData.v.3.jsx`.
- ☐ **4.5. Прочерки вместо повторяющихся слов:** `[Прочерки вместо слов]/DashInsteadWord.jsx` (путь include уже исправлен 06.07.2026). Выделите строки → запуск. Образец — `Info/Прочерки в строке термина/Math_Index.idml`.
- ☐ **4.6. Скрыть служебные номера терминов:** `HideShowNumber.v.2.jsx` (режим «скрыть»; при правках можно показать обратно).
- ☐ **4.7. Алфавитные рубрики:** `AddLetter.v.2.jsx` — выделите строки указателя → добавит буквы-заголовки. Стили оформления — `#Level1=Index`…`#Level4=Index` (отступы настройте заранее).
- ✋ **Контрольная точка этапа:** четыре оформленных указателя: диапазоны страниц свернуты, «См.»-ссылки на месте, аннотации в именном, буквы-рубрики расставлены, служебные номера скрыты.

## Риски и заметки

1. **Overflow-текст** — скрипты этапов 1 и 3 отказываются работать при вытесненном тексте. Проверяйте Preflight перед запуском.
2. **Не переименовывайте стили** `#Level…`, цвета `SkipTheWord`/`IndexColor` и группу `Index styles` — имена жестко заданы в `ForIndex.jsxinc`.
3. **Резервные копии перед этапом 3** — расстановка маркеров массово меняет документ; откат только через копию.
4. Лист «Все_Теги» xlsx — справочник тегов; листы «Корзина», «Михаилу!», «FuzzyLookup…» — служебные, в работе не участвуют.
5. Видеоуроки автора — ссылки в `Info/video.txt`; подробная методика — `Info/#IndexingOfRussianTexts.pdf`.
6. Вопросы по логике скриптов — автор: Михаил Иванюшин, dotextok@gmail.com, dotextok.ru.
7. **Пре-флайт словаря перед этапом 1** — прогнать [`tools/validate_dictionary.py`](https://github.com/gasyoun/RussianRamayana/blob/main/Litpam-Indexator/tools/validate_dictionary.py) по `.xlsx` и вычистить прозу в колонке `C`, пустые строки, хвостовые `;` (отчет — [`dictionary-validation-report.md`](https://github.com/gasyoun/RussianRamayana/blob/main/Litpam-Indexator/docs/indesign-pipeline/dictionary-validation-report.md)).
